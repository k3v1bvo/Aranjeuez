HACKATHON BY PASEO ARANJUEZ Documento Oficial de Retos 
1. Introducción 
La Hackathon by Paseo Aranjuez tiene como propósito impulsar el desarrollo de soluciones tecnológicas innovadoras que  puedan mejorar la experiencia de los visitantes, clientes, comercios y empresas que forman parte del ecosistema de Paseo  Aranjuez. 
Durante la competencia, los participantes deberán seleccionar uno de los tres retos planteados y desarrollar una propuesta  tecnológica funcional que responda a una necesidad concreta del Paseo. 
Los retos están orientados a tres áreas estratégicas: 
1. Fidelización y recurrencia de clientes. 
2. Inteligencia artificial y asistencia inteligente. 
3. Comercio digital integrado con visitas presenciales al Paseo. 
El objetivo no es únicamente desarrollar software, sino plantear soluciones que puedan tener una aplicación real dentro de  Paseo Aranjuez. 
Los equipos podrán utilizar las tecnologías, frameworks, lenguajes de programación, servicios de inteligencia artificial, bases de datos y herramientas que consideren necesarias, siempre que puedan demostrar claramente el funcionamiento de su  solución. 
2. Objetivo General de la Hackathon 
Diseñar y desarrollar soluciones tecnológicas innovadoras que permitan fortalecer el ecosistema comercial y digital de Paseo Aranjuez, mejorando la interacción entre: 
• Clientes. 
• Visitantes. 
• Tiendas. 
• Oficinas. 
• Empresas. 
• Emprendimientos. 
• Servicios. 
• Administración del Paseo. 
Las soluciones deberán buscar generar una experiencia más moderna, tecnológica e integrada. 
Además del funcionamiento técnico, se valorará la capacidad de los participantes para identificar correctamente el problema, diseñar una buena experiencia de usuario y presentar una solución que pueda evolucionar hacia un producto implementable. 
3. RETO 1 
Sistema de Fidelización de Clientes de Paseo Aranjuez 
3.1. Nombre del reto 
Paseo Points - Sistema Inteligente de Fidelización y Recompensas 
3.2. Contexto 
Paseo Aranjuez reúne diferentes negocios, tiendas, oficinas, emprendimientos y servicios que reciben diariamente clientes y  visitantes. 
Uno de los principales desafíos de cualquier espacio comercial es lograr que una persona no realice solamente una visita o  una compra ocasional, sino que tenga razones para regresar constantemente.

Por este motivo se propone desarrollar un sistema centralizado de fidelización basado en puntos, donde las compras y  determinadas actividades realizadas dentro de Paseo Aranjuez generen beneficios para los clientes. 
El sistema deberá convertir cada interacción del cliente con el Paseo en una oportunidad para generar fidelización. 3.3. Problema a resolver 
Actualmente un cliente puede visitar diferentes establecimientos y realizar diferentes compras sin que exista necesariamente un ecosistema digital común que permita:

5.2. Concepto

La lógica puede tomar como referencia la experiencia de plataformas como PedidosYa, donde el usuario puede explorar  diferentes establecimientos, revisar productos, realizar un pedido y efectuar un pago.

# Plan para ganar con Paseo Aranjuez

Vamos por partes, mano. Primero una decisión clave y luego el plan para que digan "wow".

---

## 1. ¿Cuál de los 3 retos de Paseo Aranjuez?

El documento dice algo importantísimo al final:

> "Aunque cada equipo deberá enfocarse principalmente en uno de los retos, **se valorará la capacidad de demostrar cómo la solución podría integrarse posteriormente con las otras plataformas**."

Eso es tu mina de oro. La jugada ganadora es:

**Elige PaseoYa como reto principal** (porque ya tienes Next.js + pagos + QR) **pero construye un mini-ecosistema integrado** que toque los tres:

```
PaseoYa (compra)  →  Paseo Points (puntos)  →  Jarvis (asistente IA)
```

Con un MVP real de PaseoYa y versiones ligeras de Points y Jarvis conectadas. Eso solo ya te pone por encima del 90% de los equipos.

---

## 2. Arquitectura ganadora

### Stack
- **Next.js 14/15** App Router + TypeScript
- **Tailwind + shadcn/ui** (se ve pro en minutos)
- **Prisma + PostgreSQL** (Supabase o Neon)
- **Auth.js** con roles: cliente / comercio / admin
- **Pasarela:** la que ya tengas, o QR Simple / Stripe test
- **QR:** `qrcode.react` (generar) + `html5-qrcode` (escanear)
- **Realtime:** Supabase Realtime para estados de pedido

## 4. Lo que te hace GANAR (wow features)

### Nivel 1 — Fáciles y muy vistosas
1. **QR + PIN de doble validación.** No solo escaneas el QR: pides un PIN de 4 dígitos que solo el cliente ve. Cero fraudes, se ve profesional.
2. **Mapa interactivo del Paseo** con pisos, sectores y locales. Al hacer pedido, muestras "Local 204, Piso 2, Sector B" con mapa. Librería: `react-leaflet` o un SVG propio.
3. **Notificaciones en tiempo real** al comercio cuando entra pedido (Supabase Realtime + toast).
4. **Dashboard en vivo** con ventas por tienda, top productos, pedidos por estado.
5. **Buscador global** que compara el mismo producto en varias tiendas: precio, stock, ubicación.

### Nivel 2 — Integración entre retos (esto es lo que nadie hará)
6. **PaseoYa + Paseo Points:** cada compra suma puntos automáticamente. En el checkout muestras "Ganarás 250 puntos". Al entregar el pedido, se acreditan.
7. **Paseo Points con QR personal:** el cliente tiene su QR en el perfil. El comercio lo escanea y suma puntos por compras presenciales.
8. **Jarvis integrado en PaseoYa:** un chat flotante que entiende "busco un regalo para mi novia" y te recomienda productos reales de la BD. Usa OpenAI con function calling o RAG sobre tu tabla de productos.
9. **Jarvis responde sobre pedidos:** "¿dónde está mi pedido?" → consulta la BD y responde con estado y ubicación.
10. **Recomendaciones personalizadas:** "quienes compraron esto también llevaron esto" + IA que sugiere según historial.

### Nivel 3 — El "wow" que te hace ganar
11. **Ecosistema unificado en un solo login.** Un usuario, tres módulos: compra, puntos, asistente. Muestras que no son tres apps, es **una plataforma**.
12. **Gamificación:** niveles Bronce/Plata/Oro/Platino según puntos. Barra de progreso. "Te faltan 80 puntos para Oro".
13. **Retos mensuales:** "Visita 3 tiendas diferentes este mes = 200 puntos extra". Con tracking automático.
14. **Puntos dobles en fechas especiales** configurable desde admin.
15. **Cupones digitales** que se generan al canjear puntos y se validan con QR.
16. **Detección de fraude simple:** si un comercio registra muchos puntos en poco tiempo, alerta en admin.
17. **Analytics con IA:** en el dashboard admin, un botón "Analizar con IA" que genera insights en texto: "Las ventas de tecnología subieron 30% esta semana, principalmente por audífonos".
18. **PWA instalable** (Next.js lo da casi gratis con `next-pwa`). Se ve como app nativa en el celular. En la demo lo instalas en vivo.
19. **Modo offline básico** para el escáner del comercio (guarda y sincroniza).
20. **Multi-idioma** español/inglés con `next-intl`. Paseo Aranjuez tiene turistas.

### Nivel 4 — El detalle que enamora al jurado
21. **Onboarding animado** con framer-motion.
22. **Dark mode** pulido.
23. **Skeletons de carga** en vez de spinners.
24. **Empty states** bien diseñados ("Aún no tienes pedidos, explora tiendas").
25. **Accesibilidad:** navegación por teclado, contraste, ARIA labels.
26. **Landing pública** del ecosistema Paseo Aranjuez explicando la visión.
27. **Panel de impacto:** "Este mes, PaseoYa generó 1,200 visitas presenciales al Paseo". Ese número es el argumento de negocio.

## 5. Base de datos (mínima pero bien pensada)

```prisma
model User {
  id        String   @id @default(cuid())
  email     String   @unique
  name      String
  role      Role     @default(CLIENTE)
  qrToken   String   @unique @default(cuid())
  points    Int      @default(0)
  level     Level    @default(BRONCE)
  orders    Order[]
  movements PointMovement[]
}

model Store {
  id       String    @id @default(cuid())
  name     String
  category String
  floor    String
  sector   String
  local    String
  ownerId  String
  products Product[]
  orders   Order[]
}

model Product {
  id       String  @id @default(cuid())
  storeId  String
  name     String
  price    Float
  stock    Int
  image    String?
  store    Store   @relation(fields: [storeId], references: [id])
}

model Order {
  id         String      @id @default(cuid())
  userId     String
  storeId    String
  total      Float
  status     OrderStatus @default(RECIBIDO)
  pickupCode String      @unique
  qrToken    String      @unique
  items      OrderItem[]
  payment    Payment?
  createdAt  DateTime    @default(now())
}

model OrderItem {
  id        String  @id @default(cuid())
  orderId   String
  productId String
  qty       Int
  price     Float
}

model Payment {
  id            String @id @default(cuid())
  orderId       String @unique
  method        String
  status        String
  transactionId String?
}

model PointMovement {
  id        String   @id @default(cuid())
  userId    String
  amount    Int
  reason    String
  createdAt DateTime @default(now())
}

enum Role { CLIENTE COMERCIO ADMIN }
enum OrderStatus { RECIBIDO CONFIRMADO PREPARANDO LISTO ENTREGADO }
enum Level { BRONCE PLATA ORO PLATINO }
```

## 6. Cómo integrar los 3 retos en uno

### Flujo demo estrella (guion de 5 minutos)

1. **Cliente** abre la PWA, habla con **Jarvis**: "Busco un regalo para mi novia".
2. Jarvis consulta la BD y responde: "Tienes 3 opciones: perfume en Tienda A (Bs 180), joyería en Tienda B (Bs 250), libro en Tienda C (Bs 90)".
3. Cliente elige, agrega al carrito, paga con QR.
4. Sistema genera pedido con **QR + PIN** y muestra: "Ganarás 180 puntos Paseo".
5. **Comercio** recibe notificación en tiempo real, confirma, prepara, marca "Listo".
6. Cliente ve en su celular el mapa del Paseo: "Local 204, Piso 2, Sector B".
7. Cliente llega, comercio escanea QR, pide PIN, valida, marca "Entregado".
8. **Automático:** se acreditan 180 puntos, sube de nivel, se genera cupón digital.
9. **Admin** abre dashboard: ventas, pedidos, tiendas top, y presiona "Analizar con IA" → insights en texto.
10. Cierre: "Esto no es tres apps, es **una plataforma digital para Paseo Aranjuez**".

Eso es lo que hace que el jurado diga "wow".
